## GameNative

- The [manifest](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/AndroidManifest.xml#L65-L68) exports its single-top activity and registers the [custom action and view scheme](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/AndroidManifest.xml#L103-L112). The [intent parser](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/utils/IntentLaunchManager.kt#L20-L30) names the action, `app_id`, `game_source`, optional configuration, executable and argument extras.
- For the custom action, the [parser](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/utils/IntentLaunchManager.kt#L62-L79) reads a signed Android integer and defaults an absent or unrecognized Storefront to Steam. In the ordinary ID path it [rejects nonpositive IDs and invalid sources](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/utils/IntentLaunchManager.kt#L82-L100); the executable override is a separate path. GameBridge's stricter validation remains necessary rather than relying on that upstream default.
- The view-link path parses `appid` as an integer and uppercases `gamesource`; it is a separate interface, not a permitted silent fallback in GameBridge ([source](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/utils/IntentLaunchManager.kt#L51-L61)).
- Frontend sync maps Steam, Epic, GOG, Amazon and Custom to `.steam`, `.epic`, `.gog`, `.amazon` and `.pcgame` respectively ([mapping](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt#L107-L113)); it writes the integer ID as UTF-8 decimal text ([incremental](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt#L166-L181), [full sync](https://github.com/utkarshdalal/GameNative/blob/973d31f1f7fc8270f4c3da501056b95c407a33f1/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt#L190-L213)). Exported IDs should not be assumed to be universal catalogue identifiers.

## DroidDeck

- Upstream recommends the explicit `com.droiddeck.launcher.FrontEndActivity` component rather than the launcher alias, and documents other build-variant package names ([integration guide](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/docs/frontend-integration.md#L5-L18)). The recommended component and variant availability have not been checked on a device.
- Its [intent handler](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameLaunchIntent.kt#L6-L35) accepts its own action, the GameNative action, or view requests. For extras, it accepts positive integers, nonzero long bit patterns converted to unsigned decimal, and valid decimal strings. Strings are constrained to positive unsigned 64-bit values ([validation](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameLaunchLink.kt#L3-L10)). The optional Storefront defaults to Steam; current upstream documents multiple Storefronts ([guide](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/docs/frontend-integration.md#L20-L30)). GameBridge currently rejects IDs outside its signed 32-bit policy: DroidDeck's broader range is not permission to relax it.
- Current frontend sync exports Steam and added games as `.steam`, and other store games under their store extensions, containing DroidDeck IDs ([guide](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/docs/frontend-integration.md#L41-L49); [extension selection](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameRequest.kt#L34-L55)). It also accepts additional file and link formats ([guide](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/docs/frontend-integration.md#L51-L56), [reader](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameFiles.kt#L24-L42)). These are upstream capabilities, not GameBridge's accepted input policy.
- Matching is not merely numeric equivalence: for non-Steam requests the [matching code](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameRequest.kt#L13-L21) can match source and store ID, then normalized title when enabled. File requests provide a title, whereas extras construct a request from ID and source ([file reader](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameFiles.kt#L24-L42), [extras](https://github.com/Droid-Deck/DroidDeck/blob/f29f72d5d919685f9dd8898834a640bb867d1a91/app/src/main/java/com/droiddeck/launcher/frontend/GameLaunchIntent.kt#L20-L35)). Thus the two input paths are not necessarily equivalent.

## Changes, ambiguity and limits

- The historical local DroidDeck research described a Steam-only source contract. That is stale for this HEAD: upstream commit [`dc9d1b81cc3b6f9e4e9edb98d07e0c19b2b0da9e`](https://github.com/Droid-Deck/DroidDeck/commit/dc9d1b81cc3b6f9e4e9edb98d07e0c19b2b0da9e) changed frontend file formats and store handling on 2026-11-19. Do not infer that older deployed releases include it.
- Both projects export overlapping extensions and numeric text. Neither extension nor an in-range ID proves which Target App exported a Shortcut, and shared action support does not make their ID namespaces interchangeable. A large ID alone likewise does not prove provenance. Routing, discovery, matching and a Target App picker remain outside the current authorized phase.
- GameNative's current source still uses signed integer IDs on the ordinary custom-action path; DroidDeck's broader ID handling cannot safely be sent through it without explicit validation. No narrowing or truncation should be introduced.
- The upstream guide describes URI and external-frontend workflows, but provider grants, LaunchBox behavior, installed variants, and actual game Launches were not verified in this research. Claims about releases or device behavior require version-specific source and separately authorized tests. No upstream scripts were executed, no devices modified and no production code or dependencies changed.
