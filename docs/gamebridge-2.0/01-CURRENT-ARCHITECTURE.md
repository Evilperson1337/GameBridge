# GameBridge 2.0 — current architecture audit

Audit date: 2026-11-21. Baseline commit: `4f0e22cac030b0b76735b143e0f869ea4b31b708`. This is an audit of the existing 0.1.1 codebase, not a claim that a 2.0 implementation exists. Evidence categories below distinguish repository code, direct upstream source, historical device observations, and inference. No device was accessed during this audit. Line references describe the baseline source unless otherwise stated.

## Purpose and boundaries

GameBridge is an Android/Kotlin intermediary: LaunchBox supplies a Shortcut and GameBridge validates and dispatches it to GameNative for a local game or Artemis for a remote stream ([glossary](../../GLOSSARY.md#L3-L24), [entry point](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L61-L99)). A successful activity start means **Dispatch**, not proof of a game or stream starting ([glossary](../../GLOSSARY.md#L41-L45), [GameNative result](../../app/src/main/kotlin/com/allourmedia/gamebridge/GameNativeDispatcher.kt#L9-L16)). No discovery, matching, target picker, server, CLI, background service, database, or network integration is implemented in the application sources and manifest. This is a static-repository finding, not a statement about external apps.

## Current workflows and contracts

### Input and local dispatch — repository behavior

1. The exported bridge accepts its DISPATCH action and content data; the launcher activity is separately exported and no-history ([manifest](../../app/src/main/AndroidManifest.xml#L17-L40)). Runtime triage rejects missing input, wrong action and non-content schemes ([triage](../../core/src/main/kotlin/com/allourmedia/gamebridge/core/BridgeFailure.kt#L78-L100)).
2. The bridge queries the provider's display name; for non-remote files it queries the name again and reads at most 4,097 bytes ([bridge](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L67-L91), [reader](../../app/src/main/kotlin/com/allourmedia/gamebridge/ShortcutReader.kt#L54-L84)). A changing or faulty provider can therefore affect the second query; no atomicity guarantee is established.
3. Extension matching is case-insensitive. Local files map `.gog` → `GOG`, `.steam` → `STEAM`, `.epic` → `EPIC`, `.amazon` → `AMAZON`, `.pcgame` → `CUSTOM_GAME`. All rows have the code flag `verified=true`; this flag enables dispatch and does **not** mean every storefront has independent end-to-end device verification ([table and parser](../../core/src/main/kotlin/com/allourmedia/gamebridge/core/Shortcut.kt#L15-L21)).
4. Maximum content size is 4,096 bytes. UTF-8 text optionally begins with BOM and is trimmed; the remainder must consist solely of ASCII decimal digits representing a positive signed 32-bit integer. Oversize, zero, negative, malformed and overflow IDs are rejected, not truncated ([parser](../../core/src/main/kotlin/com/allourmedia/gamebridge/core/Shortcut.kt#L55-L88)).
5. GameNative receives an explicit `app.gamenative/app.gamenative.MainActivity` intent with action `app.gamenative.LAUNCH_GAME`, integer extra `app_id`, string extra `game_source`, and NEW_TASK; the original URI and grant are not forwarded ([adapter](../../app/src/main/kotlin/com/allourmedia/gamebridge/GameNativeDispatcher.kt#L19-L42)). Missing activity and security refusal become distinct errors. There is no fallback ([adapter](../../app/src/main/kotlin/com/allourmedia/gamebridge/GameNativeDispatcher.kt#L30-L39), [bridge](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L117-L130)).

### Remote dispatch — repository behavior

A display name ending in `.art`, irrespective of case, routes to Artemis without opening or validating its contents ([parser](../../core/src/main/kotlin/com/allourmedia/gamebridge/core/Shortcut.kt#L58-L68), [bridge](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L67-L80)). The adapter sends an explicit `android.intent.action.VIEW` to `com.limelight.noir/com.limelight.ShortcutTrampoline`, using the original content URI, read-grant and NEW_TASK; missing/refused activity produces an error and there is no alternate target ([adapter](../../app/src/main/kotlin/com/allourmedia/gamebridge/ArtemisDispatcher.kt#L25-L46), [bridge](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L102-L115)). Dispatch success cannot establish that Artemis could read the file or start a stream.

### Setup, state and operational behavior

The setup activity displays a build-specific command, copies it to the clipboard and checks package visibility for LaunchBox, GameNative and Artemis ([setup](../../app/src/main/kotlin/com/allourmedia/gamebridge/SetupActivity.kt#L29-L55), [clipboard](../../app/src/main/kotlin/com/allourmedia/gamebridge/SetupActivity.kt#L106-L150), [package checks](../../app/src/main/kotlin/com/allourmedia/gamebridge/SetupActivity.kt#L197-L210)). The manifest queries only those packages and declares no application permissions ([manifest](../../app/src/main/AndroidManifest.xml#L1-L40)). Installed/visible is not evidence of correct version, configuration or a functioning game. The command must be entered into LaunchBox manually; its exact placeholder behavior is an external contract rather than something this repository implements ([setup guide](../../docs/launchbox-setup.md)).

No database, preferences, stored user configuration or durable app state is present in the application sources. Transient failure state is saved across activity recreation to avoid duplicate dispatch; errors are shown in a dismissible dialog ([BridgeActivity.kt](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L31-L55), [dialog](../../app/src/main/kotlin/com/allourmedia/gamebridge/BridgeActivity.kt#L133-L160)). Release logging records failure category, while detailed dispatch logging is gated by the debuggable flag. Signing is configured only when all four environment values are present; otherwise local release builds are unsigned ([build](../../app/build.gradle.kts#L18-L50)). The app has no config file loader; LaunchBox setup and target-app state are external.

## External compatibility evidence and limits

**Direct upstream verification on 2026-11-21:** GameNative v1.3.0's [IntentLaunchManager](https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/java/app/gamenative/utils/IntentLaunchManager.kt#L19-L71) defines the action and extras and reads `app_id` as an integer; its [manifest](https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/AndroidManifest.xml#L66-L104) exports MainActivity and declares the action. Its [GameSource enum](https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/java/app/gamenative/data/LibraryItem.kt#L6-L12) lists all five strings, and its [frontend exporter](https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt#L107-L113) maps the five extensions and [writes decimal IDs](https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt#L176-L181). This corroborates the implemented contract for that version, not future versions or every installed variant. The `.gold` package is not targeted; see [prior source analysis](../../docs/research/android-toolchain-and-gamenative.md#L167-L167).

**Historical device observations, not rerun here:** the project records a GOG direct request and an Epic LaunchBox path, plus a Steam LaunchBox dispatch on GameNative 1.4.0 where the maintainer reported Portal started ([support table](../../README.md#L21-L34), [Steam log](../../docs/investigation-log.md#L466-L476)). The GOG observation is not an end-to-end LaunchBox verification. Amazon and Custom are enabled but lack the documented device verification ([README](../../README.md#L23-L34)). The log records Artemis 20.2.6 receiving a content URI and grant via LaunchBox, starting its Game activity, and a user-reported stream; a separate release pick did not start a stream and remains unexplained ([debug observation](../../docs/investigation-log.md#L294-L322), [release observations](../../docs/investigation-log.md#L434-L451)). These records are first-hand project observations, not a fresh test or a general upstream compatibility guarantee. The exact Artemis external implementation was not independently sourced in this audit; an observed resolver filter and its limits are recorded [here](../../docs/investigation-log.md#L235-L247). No first-party LaunchBox source establishing all command substitution and grant semantics was independently verified; working behavior is limited to the recorded device flow.

**Known uncertainty:** only the observed Artemis package/version is supported by evidence; source-level stability, other versions and forks remain unknown. IDs above signed 32-bit are intentionally rejected even if another app emits them; origin of the recorded large Steam Shortcut was not proven ([investigation](../../docs/investigation-log.md#L466-L477), [research](../../docs/research/gamenative-app-id-range.md)). The external research notes include analysis and hypotheses; treat those as secondary until traced to linked upstream code or a recorded observation. Do not infer a successful Launch from Dispatch alone.

## Tests, build and release

- On this host, Java 21 and the configured SDK were available. `./gradlew --offline :core:test :app:assembleDebug check` succeeded: debug APK assembled, lint/check passed; most tasks including initial JVM tests were up-to-date. Then `./gradlew --offline :core:test --rerun-tasks` succeeded with **45 tests, 0 failures, 0 errors, 0 skipped** from the generated JUnit XML. Both commands completed 2026-11-21. Offline success depends on already cached tools/dependencies and is not a clean-machine reproducibility test.
- Core JUnit tests cover triage, size/range, formats, extensions, setup and failures ([interpreter tests](../../core/src/test/kotlin/com/allourmedia/gamebridge/core/ShortcutInterpreterTest.kt#L1-L190), [triage tests](../../core/src/test/kotlin/com/allourmedia/gamebridge/core/IntentTriageTest.kt#L1-L20)). ## Documentation, risks and handoff

The user README, setup guide, development guide, device procedure, historical G1 report, investigation log, glossary and single application-ID ADR cover the current workflow ([README](../../README.md#L1-L36), [setup](../../docs/launchbox-setup.md), [G1 report](../../docs/gamebridge-g1-launchbox-test-report-20261102.md), [ADR](../../docs/adr/0001-application-id.md)). The [original handoff](../../docs/overview/GameBridge_Implementation_Handoff.md) and research are historical and may describe earlier proposed scope/tooling; the current implementation and dated log take precedence. In particular the README describes GOG direct-request evidence more narrowly than its general verification criterion; do not upgrade it to a complete LaunchBox flow without a new observation.

Key risks: untrusted provider names/content and grant lifetime; duplicate name query; reliance on hard-coded third-party components and intent contracts; wide integer IDs from other producers; enabled but not device-verified Amazon/Custom paths; misleading installed status; partial device/version coverage; release workflow lacking automated checks; potential stale historical docs. No claim of a confirmed exploit or regression is made. Device approval and data-protection rules in [AGENTS.md](../../AGENTS.md#L17-L30) remain binding.

Suggested specialists: Android integration/test engineer for emulator and explicit-intent/grant/lifecycle regressions; security reviewer for exported input and content providers; compatibility/reverse-engineering specialist for versioned Artemis/LaunchBox contracts and storefront coverage; release engineer for CI checks and signing; documentation specialist for aligning support claims and dated guides. Defer new target discovery and selection until a separately approved phase ([project rules](../../AGENTS.md#L9-L15)).
