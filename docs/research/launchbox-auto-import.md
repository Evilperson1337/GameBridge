# Can LaunchBox import Shortcuts from `pc` automatically?: research notes

Researched 2026-11-03 from primary sources: LaunchBox's official help articles and changelog (feedback.launchbox-app.com, launchbox-app.com), forum posts by LaunchBox staff (forum.launchbox-app.com), Android developer documentation, GameNative v1.3.0 source, and read-only `adb` reads of the AYN Odin 2 Portal. Nothing on the device was installed, written, started or stopped, and no LaunchBox setting was changed. Terms follow `GLOSSARY.md`. Every claim is labelled **VERIFIED** (with its source) or **UNVERIFIED**. Forum search results were found through a web search tool; where I only saw a search summary and not the page text, the claim says so.

## Question

Today the player imports the Shortcuts in the `pc` folder (`.gog`, `.steam`, `.epic`, `.amazon`, `.pcgame` from GameNative; `.art` from Artemis) by hand each time. How viable is it for LaunchBox for Android 1.23 to import them automatically, and could GameBridge, or anything else that respects `AGENTS.md`, trigger or assist an import?

## Short answer

LaunchBox for Android has **no automatic import, folder watch, scheduled rescan or import-on-launch** that I could find, and staff have never announced one. It does have a **manual, one-gesture rescan**, **Update Games** (added in 1.21): long-press a platform and LaunchBox scans that platform's folder and adds any new games. The research expected Update Games to be the fix, but **the on-device check failed (2026-11-03): on the Windows platform, Update Games did not pick up the new Shortcut and instead reported that the user was not logged in to Steam.** So on this platform it appears to be a Steam-library refresh, not a folder rescan; the cause was not diagnosed. No LaunchBox intent, content provider or broadcast exists that GameBridge could call. Every other route either breaks an `AGENTS.md` rule (writing `Windows.xml`, a background service, an accessibility service) or is unverified and weak. **Recommendation: build nothing in GameBridge. Document the manual import as the only working path, and say plainly that Update Games does not do it.**

## 1. Does LaunchBox for Android have any auto-import?

**No built-in auto-import or folder watch. VERIFIED by absence in these primary sources (absence is not proof, see "Unverified"):**

- The official Android guide describes the Import Games wizard and says nothing about automatic import, rescans or startup scanning of ROM folders. The only startup option is "Add New Android Apps on Startup", which concerns installed Android apps, not files. Source: https://feedback.launchbox-app.com/help/articles/1026472-getting-started-with-launchbox-for-android
- The device agrees: `Data/Settings.xml` has `AddAndroidGamesOnStartup=true` (the apps option) and no import-on-startup, watch or scan key. VERIFIED, read from the device (LaunchBox 1.23, versionCode 194, `dumpsys package`).
- The Android changelog (1.0 to 1.23) lists import fixes, a network-share import (1.16), the extension whitelist (1.10), Steam import (1.22) and Update Games (1.21), but no automatic import. Source: https://launchbox-app.com/android-about/change-log . The feedback-site changelog page for 1.21 likewise mentions no "auto import": https://feedback.launchbox-app.com/changelog/launchbox-for-android-121
- Staff answer, 2024-10-21, marked as the solution (poster `faeran`, an Administrator): on Android, if you add games to a game directory you have to run the import tool again; it reports the newly found games and you can import them; a future version may add scan tools. Source: https://forums.launchbox-app.com/topic/87974-scanning-for-new-roms/ . VERIFIED as read, though I read it through a page summary, not the raw HTML.
- Feature request "Add ability to scan for added/removed ROMs" (Android), opened by a user on 2025-04-13 and set to "Open To Community" by staff (`AstroBob`) on 2025-04-17. The page mentions neither automatic nor background scanning, and gives no roadmap commitment. Source: https://feedback.launchbox-app.com/p/add-ability-to-scan-for-added-removed-roms
- The Windows desktop version does have a folder watch ("Automated ROM Imports watch platform game folders for new ROMs while LaunchBox is open and scan them again at startup", under Tools > Options > Automated Imports). The article is explicitly about LaunchBox for Windows. Source: https://feedback.launchbox-app.com/help/articles/7016587-choosing-the-right-way-to-import-your-games . This is not evidence that the Android build has it.

**Manual rescan: Update Games (1.21, released 2025-12-04). VERIFIED (staff):**

- "When you long press a platform and choose Update Games, LaunchBox scans the files in that folder, compares them with your library, and automatically adds any new games it finds. There is also an optional toggle to remove games whose ROM files no longer exist in the folder. LaunchBox never modifies or deletes ROMs." Source: https://feedback.launchbox-app.com/changelog/launchbox-for-android-121 (the page text was read through a summarising fetch; the quoted lines are as returned).
- Beta 2 changelog by `faeran` (Administrator), 2025-10-14: "Platforms can now be updated. Long press a platform to access the update option." and "LaunchBox will scan the platform directory for new and removed ROM files, add new ones, and optionally delete removed ones." Source: https://forums.launchbox-app.com/topic/92245-launchbox-for-android-121-beta-thread/ (also repeated in the 1.21 release thread by `AstroBob`, Staff: https://forums.launchbox-app.com/topic/93112-launchbox-for-android-121-released/ ).
- 1.23 fixes: "Fixed NAS re-imports and Update Games scans incorrectly adding, skipping, or removing existing games", "Update Games now shows how many games were relinked and lists any that could not be matched." Source: https://forums.launchbox-app.com/topic/94003-launchbox-for-android-123-beta-thread/ (by `x4ml`, Staff) and https://launchbox-app.com/android-about/change-log .
- Date discrepancy to note: the feedback-site changelog dates 1.23 as 2026-08-04, the launchbox-app.com change log as 2026-10-09. The device shows 1.23 installed on 2026-10-28. Not important for this question.

**Hidden options.** On the device, every platform XML has a `<DisableAutoImport>false</DisableAutoImport>` element, and the Windows platform has `<PlatformUri>content://com.android.externalstorage.documents/tree/primary%3AGames%2Fpc</PlatformUri>` (only Windows and Nintendo Switch have a value; the other platforms have it empty). VERIFIED, read from `Data/Platforms/*.xml`. **What this means is UNVERIFIED.** `DisableAutoImport` is an existing element; its presence suggests the shared platform model has a per-platform auto-import switch (the desktop app has a per-platform disable, per search summaries of the 13.12/13.17 forum threads, which I did not read in full). I found no Android documentation or staff post saying the Android app acts on it. `PlatformUri` is evidence that LaunchBox holds a Storage Access Framework tree for the `pc` folder, which is what Update Games would need; it is not evidence of a watcher. No setting in `Settings.xml` or the UI docs exposes either value, and I did not change or test them.

**Roadmap statement.** None found. The only forward-looking sentence is `faeran`'s "a future version may make this clearer in the app and add scan tools" (2024), which Update Games then delivered as a manual action.

## 2. How the import works

**Wizard (Main Menu > Import Games). VERIFIED from the official guide** (https://feedback.launchbox-app.com/help/articles/1026472-getting-started-with-launchbox-for-android; read through a summarising fetch):

- Options: Folder of Games to Import, Platform for Imported Games, Region to Prioritize, File Extension Filter, Combine ROMs with Matching Titles, Import Games from Subfolders, Use Folder Names, Use MAME Metadata, Force Import Duplicate Games, Proceed with Import. The scan list is shown for review before importing.
- **Extensions.** The filter defaults to "All Files" and can be limited to chosen extensions; the guide "does not list supported file types". An extension whitelist was added in 1.10 (2023-10-30, change log). Consequence: nothing in the docs restricts `.gog`/`.steam`/`.epic`/`.amazon`/`.pcgame`/`.art`, and the device shows all of `.gog`, `.epic`, `.amazon` and `.art` were imported. Whether LaunchBox treats an unknown extension differently during Update Games (as opposed to the wizard) is UNVERIFIED.
- **Platform.** Chosen by the user. If the folder name exactly matches a supported platform, LaunchBox may preselect it. A `pc` folder does not match "Windows", so the player picks Windows once. Windows exists as a platform from 1.22 (change log).
- **Title.** From the file name, matched against the LaunchBox Games Database ("Good file names help a lot"); a wrong match can be fixed with Edit Metadata. Observed on the device (`Windows.xml`): `Akalabeth_ World of Doom.gog` became Title `Akalabeth World of Doom`; `ABZU.epic` became `ABZÛ` with database notes; `Desktop.art` became `Casual Desktop Game` (a database match, not the Artemis app name); `Cuphead (GOG).art` became `Cuphead: 'Don't Deal with the Devil'` with `<Version>(GOG)</Version>`. VERIFIED (device). Consequence: imported titles can differ from the Shortcut file name, and a database match can attach metadata to the wrong game (the `Desktop.art` match is an example).
- **Duplicates.** "Force Import Duplicate Games ... imports games even if they appear to already exist ... leave this off." "Combine ROMs with Matching Titles" groups regional versions, revisions and multi-disc files under one entry (guide). Device: `Settings.xml` has `ForceImportDuplicateGamesThatExist=false`. How "already exists" is decided (path or title) is not documented: UNVERIFIED. Relinking by file name for Update Games is mentioned only in the 1.23 beta notes (above).
- Media is not downloaded during import; LaunchBox may restart afterwards (guide).

**Files written. VERIFIED (device, read-only):**

- All game records live in one XML per platform: `/storage/emulated/0/LaunchBox/Data/Platforms/Windows.xml` (seven `<Game>` records, `ApplicationPath` = the Shortcut under `/storage/emulated/0/Games/pc/`, `<DateAdded>` timestamps). The same file holds the `<Platform>` block with `DefaultEmulator`, `CustomEmulatorLaunchArguments`, `PlatformUri` and `DisableAutoImport`. This matches `docs/investigation-log.md` (2026-11-02, "Working LaunchBox configuration").
- LaunchBox writes timestamped backups of each platform XML in `Data/Platforms/Backups/` and of `Settings.xml` and `FilterSets.xml` in `Data/Backups/` (many files dated 2026-11-03, written while the app was used).
- `Data/Settings.xml` holds the import defaults (`ImportGamesFromSubfolders`, `UseFolderNamesInsteadOfRom`, `ForceImportDuplicateGamesThatExist`, ...).

**Observed gap on this device.** `Games/pc` holds eight Shortcuts; `Windows.xml` has seven games. `Cuphead.art` (created 2026-11-03 13:59) has no game record. This is consistent with LaunchBox not importing new files by itself, but it is a single observation and I do not know whether the player skipped it on purpose. UNVERIFIED as evidence of anything beyond "it is not there".

## 3. Options for GameBridge or anything else

| Option | Verdict | Reason |
|---|---|---|
| LaunchBox-provided intent, broadcast or content API to trigger an import | **Not viable** (as far as inspectable) | `dumpsys package com.unbrokensoftware.launchbox` (versionCode 194) shows `MainActivity` (MAIN/LAUNCHER, plus an https filter on `www.launchbox-app.com/android-license-registration`), `HomeActivity` (MAIN/HOME), `ProfileInstallReceiver` (androidx), a media session service, and file/Sentry/startup providers. No import action, no exported import receiver, no import provider. VERIFIED (device). Not exhaustive: a component with no intent filter can still be exported; I did not read the manifest XML, and a dynamically registered receiver would not show. No docs or staff post mention such an API (searches found none). |
| Write the platform XML (`Windows.xml`) ourselves | **Not viable, and forbidden** | `AGENTS.md` says "never modify LaunchBox or its files", and `MANAGE_EXTERNAL_STORAGE` is also barred. Risks: LaunchBox rewrites and backs up this file during normal use (many backups, 2026-11-03), so a concurrent write can be lost or corrupt the library; the file also carries the Setup command, so a bad write breaks every Windows game; LaunchBox is a .NET MAUI app that keeps the library in memory (UNVERIFIED), so edits made while it runs may be overwritten; no schema is documented. Note the device's `Android/data` / scoped-storage rules would also block a plain app from writing `LaunchBox/Data/` without the all-files permission. |
| Storage Access Framework tree grant to `pc` plus a read-only "unimported Shortcuts" list in GameBridge | **Viable technically, weak value** | `ACTION_OPEN_DOCUMENT_TREE` gives read access to a chosen directory without any permission, and `takePersistableUriPermission` keeps it across reboots; `Games/pc` is not one of the restricted directories (those are the storage root, `Download` and `Android/data`/`obb`). Source: https://developer.android.com/training/data-storage/shared/documents-files . GameBridge could list files in `pc` and compare with... what? It cannot read `Windows.xml` (no permission, and reading LaunchBox's folder needs a second grant of `/LaunchBox/Data`, which a SAF picker may allow but it is another user step). Without that comparison, the list is just the folder listing. Also adds a screen, a stored grant and untrusted-file parsing to an app whose job is dispatch. It could not import anything either way, so it does not remove the manual step. It is also "building discovery/matching early", which `AGENTS.md` forbids for this phase. |
| Android file observers (`FileObserver`, `ContentObserver`) | **Not viable** | They only report events while a process is alive and watching; the `FileObserver` docs describe an inotify watcher (https://developer.android.com/reference/android/os/FileObserver). Keeping one alive when GameBridge is not on screen requires a background or foreground service, which `AGENTS.md` forbids. Even if it fired, there is nothing to call in LaunchBox (row 1). A periodic WorkManager job is the same objection in a different form (the system decides when it runs: "The exact time that the worker is going to be executed depends on the constraints ... and on system optimizations", https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started ). |
| Tasker or other external automation | **Not viable as a shipped GameBridge feature; unknown as a personal setup** | Tasker could watch the folder and open LaunchBox, but nothing it can send makes LaunchBox import (row 1); it would need an accessibility service or UI automation to press Update Games, which `AGENTS.md` forbids us to ship, and the player would install a second large app. Whether an accessibility-driven macro is reliable on LaunchBox's gamepad UI: UNVERIFIED, not tested, and out of scope. |
| GameNative-side hook | **Not viable today; unknown upstream** | GameNative v1.3.0 `FrontendSyncManager.kt` only writes the export files (and re-syncs them); a grep for `launchbox`, `broadcast` and `intent` finds nothing, and its comment names ES-DE, not LaunchBox (VERIFIED for that one file: https://github.com/utkarshdalal/GameNative/blob/v1.3.0/app/src/main/java/app/gamenative/sync/FrontendSyncManager.kt ). Even a hook there would have no LaunchBox API to call. We do not modify GameNative (`AGENTS.md`). Artemis would have the same limit. Whether upstream would accept such a feature: unknown. |
| Desktop LaunchBox/Big Box sync route | **Possible only for a different workflow; unknown for this one** | Desktop has real auto-import (see section 1) and exports/syncs to Android devices (a forum thread on exporting from Windows to Android is in the search results, not read). But the Shortcuts are created on the handheld by GameNative and Artemis, so a PC would have to be in the loop, the sync model for Windows-platform entries with `ApplicationPath` on the device is unknown, and a feedback post asks for incremental Android device sync (not built, per the search summary of https://feedback.launchbox-app.com/p/add-incremental-sync-for-android-device-profiles ). Not pursued. |
| Update Games (LaunchBox's own, manual) | **Not viable on this platform (observed)** | Staff documentation describes a folder rescan (section 1), but on the Windows platform on the Odin it did not add the new Shortcut and complained about a missing Steam login (see 'Result of the on-device check'). |

## 4. Recommendation

**Build nothing in GameBridge.** An import trigger does not exist for us to call, and every substitute either breaks a rule or does less than the manual import. LaunchBox's own Update Games does not import Shortcuts on this platform (observed), so the manual import wizard stays the way to add new Shortcuts. The smallest useful change is **documentation**: `docs/launchbox-setup.md` should keep the manual import as the path and say that LaunchBox does not import on its own and that Update Games on the Windows platform did not pick up Shortcuts (it asked for a Steam login). The one `Cuphead.art` seen in `pc` without a game record shows what "not imported" looks like.

If the maintainer wants more later, the only piece that fits `AGENTS.md` is a **request to LaunchBox**: comment on the "Scan for added/removed ROMs" feature request asking for scheduled or on-launch scanning of non-Steam platforms on Android. That is not a code task for this repo.

## Result of the on-device check (2026-11-03)

Reported by the maintainer, who ran it on the Odin; the agent did not see the screen.

- **VERIFIED (user-reported):** long-pressing the Windows platform and choosing Update Games did not add the new Shortcut. LaunchBox reported that the user was not logged in to Steam.
- **UNVERIFIED (inference):** that Update Games on this platform only checks a Steam library. The message suggests it, but no source states it, and it is not known whether Update Games behaves differently on a platform created by the folder import. How to verify: ask in the LaunchBox forum, or test Update Games on a platform that has no Steam link, with a backup first.
- Not tried: the other Update Games options on that screen, and a cold start with no manual action.

## Unverified / how to verify

1. **Why Update Games asked for a Steam login on the Windows platform, and whether any Update Games mode rescans a folder of Shortcuts.** The first check failed (see 'Result of the on-device check'); the cause is unexplained. Verify: ask on the LaunchBox forum, or read the screen's options with the maintainer; any further test changes LaunchBox's library, so back up `Windows.xml` first and treat it as an "ask first" action under `AGENTS.md`.
2. **That no auto-import exists in 1.23 and that `DisableAutoImport` is unused on Android.** Verify: with LaunchBox restarted by the maintainer, drop a new Shortcut into `pc` (a temporary copy, approved in advance) and check `Windows.xml` after a cold start and after some minutes. A positive result would overturn the short answer. I could not do this without writing to the device.
3. **Whether LaunchBox exposes any exported component or intent beyond what `dumpsys` showed.** Verify: `aapt2 dump xmltree` on the installed LaunchBox base APK (pulled with `adb pull`, read-only, from the path `pm path` gives) and read `AndroidManifest.xml` for `exported`, services and receivers. Dynamic receivers need a decompile and are out of scope.
4. **How LaunchBox decides a game "already exists" during import or Update Games** (path, title, file name). Part of check 1: re-run Update Games twice and confirm the count stays the same; then import a copy with a new file name.
5. **Whether the Android version has any staff statement I missed.** I read pages through summarising fetches and web-search summaries, not raw HTML, and I did not read the 13.12/13.17 desktop threads, the Android 1.22 release thread, or the 1.21 beta thread in full. Verify: search forum.launchbox-app.com Android sections for "automatic", "watch", "on startup", "update games" and read any hit by `faeran`, `AstroBob`, `x4ml` or `Jason Carr`.
6. **Desktop-sync route.** Not investigated beyond search results. Verify only if the maintainer wants a PC in the loop.
