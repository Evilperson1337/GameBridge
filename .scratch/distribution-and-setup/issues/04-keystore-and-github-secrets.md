# 04: Keystore and GitHub secrets

**What to build:** The maintainer has a release keystore and the GitHub Actions secrets that ticket 03 reads, with an offline backup of the keystore. A `/wizard` script walks the maintainer through generating the keystore, setting the secrets and checking the backup. The README states that losing the key means players must uninstall before updating.

**Blocked by:** 03 (Signed release build in CI), which defines the secret names.

**Status:** ready-for-human

- [ ] A keystore is generated by the maintainer and never committed.
- [ ] The secrets named by the workflow exist in the GitHub repository.
- [ ] An offline backup of the keystore exists and its location is known to the maintainer, not recorded in the repo.
- [x] The wizard script is in the repo without any secret values. `scripts/setup-release-signing.sh`: `bash -n` passes, the wizard library is byte-identical to the template, the four `set_secret` names match the `secrets.*` references in `.github/workflows/release.yml`, and its keytool, hash and base64 commands were exercised against a throwaway keystore outside the repo. The wizard itself has not been run end to end (it needs you).
- [x] The key-loss warning is in the README (added in ticket 05, README line starting "Releases are signed by the maintainer's key").

## Notes

Run `scripts/setup-release-signing.sh` from your own terminal. It stops at: GitHub login, the GitHub repository (this checkout has no remote), the keystore path and passwords, the offline backup, and setting the secrets. Criteria 1-3 stay open until you have run it. It does not record the backup location or write passwords to any file.
